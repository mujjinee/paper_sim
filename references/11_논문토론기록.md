## 1. Real-time 가격의 역할과 불확실성 문제



### 현재 모델에서 real-time 가격의 위치



목적함수(Eq. 1a)에는 real-time price가 파라미터로 이미 들어있습니다. "초과분을 real-time에서 팔면 얼마 버는가"를 계산하는 데 쓰입니다.



하지만 **학습(training) 단계에서만** 쓰입니다. 학습할 때는 "과거에 실제로 real-time 가격이 얼마였는지"를 이미 알고 있으니까 그걸 넣어서 계수를 맞춥니다.



문제는 **실전(테스트) 단계**입니다. 내일 커밋을 결정하는 시점에는 "내일 real-time 가격이 얼마일지" 아직 모릅니다. 그래서 지금 모델은 이걸 "확률적(stochastic) 파라미터"로 취급하고, 회귀모델의 입력변수로는 쓰지 않습니다 (AR은 과거 발전량만, MLR은 날씨 변수만 입력으로 씀).



### 변수로 넣는다면?



**발전량 예측 모델의 입력변수로 real-time 가격을 넣는 경우**: 발전량(태양광)은 날씨가 결정하는 물리량이라 가격과 인과관계가 없습니다. 다만 실제로는 상관관계가 있을 수 있습니다 — 재생에너지 발전량이 많은 시간대일수록 공급 과잉으로 real-time 가격이 떨어지는 경향(이른바 "duck curve" 효과)이 실제 시장에 존재합니다. 이 상관관계를 반영하면 예측력이 오히려 좋아질 수도 있습니다.



**가격 자체를 별도로 예측해서 커밋 결정에 반영하는 경우**: 현재 모델은 "가격은 역사적으로 주어진 값"으로 두고 발전량만 예측합니다. 실전에서는 가격도 미래값이라 불확실합니다. 가격까지 예측 대상에 포함시키면, 발전량 예측 오차 + 가격 예측 오차가 같이 커밋 결정에 영향을 주는 구조가 되어 모델이 훨씬 복잡해집니다. 두 예측 오차가 서로 상쇄되는지 증폭되는지도 따져봐야 합니다.



### 추천 방향



무작정 "가격을 변수로 추가"보다는, "real-time 가격의 불확실성을 확률적으로 모델링해서 커밋 결정에 반영" 하는 방향(예: 가격 시나리오 기반 stochastic 버전)으로 제안하는 게 더 좋습니다. 현재 논문이 이미 가격을 "결정론적 파라미터"로 단순화한 한계를 정확히 짚는 확장이 됩니다. 단, 모델 복잡도와 데이터 요구량이 크게 늘어난다는 트레이드오프가 있습니다.

## 2. 이 논문의 위치: Decision-Focused Learning 흐름



이 논문은 사실 "예측과 최적화를 통합해서 학습한다"는 더 큰 연구 흐름의 한 응용 사례입니다:



- **Decision-focused learning** (결정 중심 학습)

- **End-to-end learning** (끝에서 끝 학습)

- **Smart Predict-then-Optimize** (스마트 예측 후 최적화)



상위 흐름의 핵심 논문들:

- Elmachtoub & Grigas (2022) — "Smart Predict-then-Optimize"

- Donti et al. — 미분 가능한 최적화 레이어 접근

## 3. 제안 확장 아이디어 (우선순위 순)



### ① 딥러닝 기반 예측으로 교체 (가장 자연스러운 확장, 구현 난이도 중)



현재 논문은 AR/MLR이라는 선형 모델만 씁니다. 실제로 이 문제는 비선형 예측(LSTM, gradient boosting 등)이 정확도를 훨씬 높일 수 있는 영역입니다.



하지만 **비선형 모델을 쓰면 Eq.9/10처럼 손실함수+최적화를 하나의 선형 최적화 문제로 풀 수 없게 됩니다**. 미분 가능한 최적화 레이어(Donti et al. 식 접근)가 필요합니다.



**발표 포인트**: "선형이라 풀기 쉬웠던 것"의 트레이드오프를 보여주는 좋은 지점입니다.



### ② Real-time 가격의 불확실성을 확률적으로 반영



현재 모델은 학습 시 과거 실제 가격을 알고 있다고 가정(결정론적)합니다. 실전 배포 시에는 가격도 불확실합니다. 가격 시나리오 기반 stochastic 확장이 실전 적용성을 높이는 방향입니다.



### ③ 포트폴리오/복수 자원으로 확장



현재는 태양광 단일 자원, 단일 사업자입니다. 풍력+태양광 포트폴리오, 또는 배터리 저장장치(ESS)를 함께 최적화하면 "저장으로 시프트"라는 새로운 결정 변수가 생겨 문제가 훨씬 현실적이고 흥미로워집니다. **ESS 결합은 최근 실제 업계 트렌드와도 맞아떨어져서 발표 임팩트가 큽니다.**



### ④ 리스크 회피(Risk-Aversion) 명시적 반영



현재 목적함수는 기대값(expected profit) 최적화입니다. CVaR(Conditional Value-at-Risk) 같은 리스크 척도를 추가하면, "사업자가 리스크를 얼마나 감수할지"를 λ1/λ2 외에 또 다른 다이얼로 조절할 수 있어 논문의 프레임워크와 자연스럽게 결합됩니다.

## 5. AR vs MLR 모델 비교



### AR (Auto-Regressive, 자기회귀모델)



**핵심 아이디어**: "과거의 나 자신만 보고 미래를 예측한다"



- 오직 그 발전소 자신의 과거 발전량 데이터만 사용합니다. 날씨 정보 같은 외부 데이터는 전혀 안 씁니다.

- "어제, 그리고 그 전날들의 발전량 패턴을 보면, 내일도 비슷한 패턴일 것이다"라는 논리입니다.



**직관적 예시**: 오전 10시 발전량을 예측한다고 하면,

> 오늘 10시 예측값 = a×(어제 10시 발전량) + b×(그저께 10시 발전량) + ... + c



여기서 a, b, c 같은 계수(가중치)를 과거 데이터로 학습해서 구합니다. "며칠 전 이 시간대 발전량이 얼마였는지"만 갖고 예측하는 셈입니다.



**장점**: 날씨 데이터 등 외부 정보가 필요 없어 간단함.

**단점**: 날씨가 갑자기 바뀌면(예: 어제는 맑았는데 내일 갑자기 비 예보) 전혀 반영이 안 됨. 순전히 "과거 패턴의 연장"이기 때문.

**논문 명칭**: endogenous(내생적) 접근 — 오직 자기 자신의 시계열 데이터만 쓴다는 뜻.



### MLR (Multiple Linear Regression, 다중선형회귀모델)



**핵심 아이디어**: "날씨 예보 등 외부 정보를 보고 미래를 예측한다"



- 여러 개의 외부 변수(기상예보 데이터)를 가지고 발전량을 예측합니다.

- 논문에서 실제로 쓴 변수는 backward stepwise로 골라낸 3개: SSRD(지표면에 도달하는 태양광 복사량 예보), TSR(대기 상단 순 태양 복사량), Hour(시간대).



**직관적 예시**:

> 내일 10시 발전량 예측값 = w1×(내일 10시 태양복사량 예보) + w2×(대기상단 복사량 예보) + w3×(시간대) + 상수



즉 "내일 날씨 예보가 이러이러하다면, 발전량은 대략 이 정도일 것이다"를 선형 공식으로 계산합니다. w1, w2, w3 같은 계수는 과거 데이터(과거의 날씨예보 vs 실제 발전량)로 학습해서 찾습니다.



**장점**: 날씨 변화를 직접 반영하니까 AR보다 훨씬 정확함 (nRMSE 21%대 vs AR 34%대).

**단점**: 정확한 날씨 예보 데이터가 있어야 함(예보가 틀리면 예측도 같이 틀림).

**논문 명칭**: exogenous(외생적) 접근 — 외부 데이터를 쓴다는 뜻.



### 한 줄 비교



| | AR | MLR |

|--|----|-----|

| 입력 | 자기 과거 발전량만 | 날씨 예보 등 외부 변수 |

| 별명 | endogenous(내생적) | exogenous(외생적) |

| 비유 | "예전에 이랬으니까 내일도 이럴 것" | "내일 날씨가 이렇다니까 발전량은 이럴 것" |

| 논문 실험 정확도 | 낮음 (nRMSE 34.76%) | 높음 (nRMSE 21.76%) |



### "선형 모델"이라는 게 무슨 뜻인가



두 모델 다 곱하고 더하는 것(계수 × 변수 + 계수 × 변수 + ...)만으로 예측값을 계산합니다. 신경망(LSTM 등)처럼 복잡한 비선형 변환이 없다는 뜻입니다.



**이게 왜 중요한가**: 확장 아이디어 ①(비선형 모델로 교체)이 바로 이 지점을 건드립니다. "선형이라서 최적화 문제(Eq.9, 10)를 깨끗하게 풀 수 있었는데, 비선형으로 바꾸면 그 장점이 사라진다"는 트레이드오프입니다.

## 6. 딥러닝 기반 확장 3가지 접근법: 구현 및 실험 결과 (2026-08-24)



### 실험 환경



- 데이터: GEFCom2014 전체 기간, 300일 학습, 100일 테스트

- MISO 가격 데이터 없음 → nRMSE 만 평가 (optimality gap 불가)

- Zone 1, UTC 00:00~11:00 하루 12시간

- 스크립트: `run_deep_learning_experiment.py`



### 접근법 ①: 두 단계 분리 — 예측 정확도만 최적화



**핵심**: 기존 AR/MLR 을 비선형 모델로 교체. 최적화 통합은 버리고 예측 정확도만 높임.



**XGBoost (34.23%)**:

- 과거 12일 같은 시간 + 기상 변수 12개 + 시간대 순환 인코딩 입력

- n_estimators=200, max_depth=6, learning_rate=0.05

- **현재까지 가장 낮은 nRMSE(34.23%)**. 기존 MLR(12vars) 35.67% 보다는 개선

- 하지만 논문 21.76% 과 57% 차이 → 학습 기간/테스트 기간 차이 여전



**LSTM (46.39%)**:

- PyTorch 기반, 2-layer LSTM, hidden=64

- 입력: 과거 12일 × 12시간 시계열, 출력: 다음 날 12시간

- **XGBoost(34.23%)보다 훨씬 나쁨** → 학습 데이터(300일×12시간=3,600)가 너무 적어 과적합

- 50 epoch 학습 시 loss 0.000330 대로 낮지만, 테스트 성능은 낮음



**① 결론**: 데이터가 3,600일 정도로 작으면 tree 기반 모델이 딥러닝보다 훨씬 효율적. GEFCom2014 전체 821일을 다 써도 부족할 수 있음.



### 접근법 ②: Neural Net + 최적화 손실 (Decision-Focused Learning)



**핵심**: 예측 모델이 예측 정확도만 높이는 것이 아니라, day-ahead 커밋 결정에서 profit 을 최대화하는 방향으로 학습. asymmetric loss 로 under-prediction(실제 > 예측, shortage) penalty 가 높을 때 더 큰 가중치.



**결과 (139.70%) — 수렴 실패**:

- 128→64→32→sigmoid MLP 구조

- Asymmetric MSE loss: w_under=2.0, w_over=0.75 (penalty_rate=0.5)

- Early stop at epoch 31

- 테스트 nRMSE 139.70% → 학습 데이터 분포와 테스트 분포 차이过大로 과적합

- MISO 가격 데이터가 없어서 실제 optimality gap 을 손실에 넣을 수 없음



**② 결론**: 논문이 MISO 가격 데이터를 학습 손실에 썼던 이유. 가격 없이 proxy 손실(asymmetric MSE)로 대체하면 학습이 불안정. MISO 가격 데이터 확장이 선행되어야 의미가 있음.



### 접근법 ③: REINFORCE — Profit Reward 기반 학습



**핵심**: Neural Net 이 예측값을 action 으로 보고, profit 을 reward 로 학습. 최적화 문제를 미분 가능할 필요가 없음. REINFORCE estimator 사용.



**결과 (202.92%) — 수렴 실패**:

- 50 episode 학습

- Reward = asymmetric MSE (MISO 가격 없어 proxy 사용)

- Baseline(subtract mean) 으로 variance 감소 시도했지만 여전히 불안정

- 테스트 nRMSE 202.92% → REINFORCE estimator variance 문제



**③ 결론**: REINFORCE 는 reward signal 이 weak 할 때 매우 불안정. MISO 가격으로 진짜 profit 을 계산해야 할 수도 있지만, 3,600일 데이터로는 policy gradient 의 variance 를 줄이기 어려움.



### 종합 비교



| 모델 | nRMSE | 비고 |

|------|-------|------|

| AR | 49.33% | baseline |

| MLR(12vars) | 35.67% | 기존 최선 |

| MLR(sw-3vars) | 36.62% | stepwise |

| **XGBoost (①)** | **34.23%** | **현재 가장 낮음** |

| LSTM (①) | 46.39% | 데이터 부족으로 과적합 |

| DF-NN (②) | 139.70% | 수렴 실패 |

| REINFORCE (③) | 202.92% | variance 문제 |



### 핵심 인사이트



1. **XGBoost 가 최선이지만 여전히 논문과 57% 차이**: 학습/테스트 기간(300/100일 vs 논문의 300/100일) 은 같지만, 테스트 기간이 다른 시기이므로 비교 불가

2. **접근법 ②③(MISO 없이)는 아직 성숙하지 않음**: 가격 데이터가 있어야 profit 기반 손실이 의미를 가짐

3. **딥러닝은 3,600일 데이터로 부족**: tree 기반 모델이 더 효율적

4. **논문의 "선형이라 쉬웠다"는 핵심 트레이드오프를 실제로 확인**: 선형 AR/MLR 은 최적화 통합 가능하지만 정확도 한계가 있음. 비선형 모델로 바꾸면 정확도는 높일 수 있지만 최적화 통합이 불가. 현재 XGBoost(34.23%)가 그 중간 지점.

### MISO 가격 → 불명확



| 항목 | 논문 내용 |

|------|-----------|

| 출처 | MISO (Midcontinent ISO) 언급, 참조 [20] |

| **노드/허브** | **밝히지 않음** |

| **정확한 기간** | **밝히지 않음** — "Data will be made available on request" |

| Fig. 1 | "for 4 months" 만 언급 |

| DA + RT 둘 다 | 사용은 확인 |



**핵심: MISO 가격 데이터의 정확한 노드와 기간을 밝히지 않음.** "Data will be made available on request" 라는 것은 논문 저자가 직접 가공한 데이터를 요청자에게 보내준다는 뜻. 즉 MISO 아카이브에서 어떤 노드를 뽑았는지, 어떤 날짜 범위를 썼는지는 논문만으로는 알 수 없음.



### 우리가 할 수 있는 것



1. **MISO System** 전체 허브 (현재 우리가 다운로드한 것) — 가장 합리적인 추측

2. 그러나 300일 학습/100일 테스트로 최적화 재현하려면 **GEFCom2014 Solar 기간(2012.04~2014.07)** 과 겹치는 MISO 데이터 필요

3. 현재 2014년 1~4월 4개월만 보유 → **2012년 4월~2014년 7월**까지 확장해야 함

4. MISO 월별 아카이브 (da_pr_xls.zip, rt_pr_xls.zip) 에서 추가 다운로드 가능



### 결론



- GEFCom2014: 명확하게 명시 → 우리가 정확히 재현 중

- MISO 가격: 노드+기간 불명확 → **논문만으로는 정확한 재현이 제한적**

- 최적화/gap 재현을 위해 MISO 확장이 필수이나, 어떤 노드를 쓸지는 저자에게 확인해야 함

4. **접근법 ②③** (DF-NN, REINFORCE) 은 MISO 가격 없이 수렴 실패
