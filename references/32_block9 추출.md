왜 이럴 수 있는지 (가능한 원인)
SSRD/TSR을 원시값 그대로 사용: build_merged_for_simulation.py가 그랬던 것처럼 이 스크립트도 VAR169/VAR178을 가공 없이 그대로 씁니다. GEFCom2014의 이 변수들은 흔히 "예보 시작 시점부터 누적된 값"이라 시간이 지날수록 커지는 특성이 있을 수 있는데, 그렇다면 원시값을 그대로 회귀에 넣는 게 예측력을 떨어뜨렸을 수 있습니다(하루 안에서 값이 계속 누적/증가하는 패턴을 "발전량 자체의 패턴"으로 착각하게 만듦).
Hour를 숫자 그대로(0~11) 하나의 연속변수로 사용: 논문 Eq.(6) 그대로긴 하지만, 시간대 0시와 11시 사이에 발전량이 선형 관계가 아닐 수 있어 이 단순화가 손해였을 수 있습니다.
표준화(스케일링) 없이 학습: SSRD/TSR/Hour의 스케일이 서로 크게 다른데 정규화를 안 해서 LAD 회귀가 잘 안 맞았을 가능성도 있습니다.
AR은 태양광 자기 자신의 과거 패턴만 쓰니 이런 기상변수 관련 문제에서 자유롭고, 그래서 이번 블록에서 오히려 MLR보다 잘 나온 것으로 보입니다.

readme.md의 설명대로, VAR169/VAR178은 "01,02,...,23,00" 24시간 예보 묶음 안에서 누적되는 값이라 원시값을 그대로 쓰면 사실상 "지금까지 누적된 총량"을 입력으로 준 셈이었습니다(하루가 지날수록 계속 커지는 값). 이걸 시간별로 차분해서 그 시간 한 시간 동안의 증분(dSSRD, dTSR)으로 바꿔주니, 실제 발전량과의 관계가 훨씬 명확해진 것으로 보입니다 — 지난번 제 가설("원시 누적값을 그대로 써서 손해였을 것")이 맞았습니다.

deaccumulate() 함수는 operational_corrected의 deaccumulate_source와 동일한 로직입니다:

zone·시간순 정렬
(TIMESTAMP - 1시간)을 날짜만 남겨서 "묶음 이름표(bundle_date)"로 사용 → 이러면 D일 01:00부터 D+1일 00:00까지 24개 행이 전부 같은 묶음으로 묶임
묶음 안에서 diff()로 시간별 증분 계산, 묶음의 첫 시간만 원래 누적값을 그대로 사용
음수 증분도 임의로 0으로 안 바꾸고 그대로 보존

### paper_proposed_block9.py의 현재 profit 함수 (정리)

def imbalance_components(actual, commitment):
    surplus = np.maximum(actual - commitment, 0.0)      # 실제 > 약정 -> 잉여
    shortage = np.maximum(commitment - actual, 0.0)      # 약정 > 실제 -> 부족
    return surplus, shortage

def profit_per_observation(actual, commitment, day_ahead_price, real_time_price, penalty_rate=PENALTY_RATE):
    surplus, shortage = imbalance_components(actual, commitment)
    penalty = penalty_rate * day_ahead_price
    return CAPACITY_MW * DURATION_HOURS * (
        day_ahead_price * commitment
        + real_time_price * surplus
        - penalty * shortage
    )
논문 Eq.(1a) 그대로 3항입니다 — run_experiment_comparison.py에 있던 - rt_price * shortage 항(부족분에 RT가격을 이중으로 물리는 항)이 여기엔 없습니다. 이게 지난번에 논문 원문(DP_t·x_t + RP_t·y'_t − PC_t·y''_t)을 재확인해서 고친 버전입니다.

### 지금 gap(2.63.7%)이 논문(1215%)보다 훨씬 작게 나온 이유를 실제 데이터로 확인해봤습니다.

원인 1: 3항 이익함수 구조 자체가 예측오차를 관대하게 봐줌
우리가 쓰는 논문식 이익함수(Eq.1a)는 부족분에 벌금(0.5×DA가격)만 물리고, 실시간가격은 안 물립니다. 이 구조에서 시간당 손실을 직접 풀어보면:

과소예측(commit < 실제): 손실 = (DA − RT) × 부족한 양
과대예측(commit > 실제): 손실 = 0.5 × DA × 초과한 양 — 그리고 DA<RT인 시간대에 걸리면 이 "손실"이 오히려 마이너스(즉 오라클보다 더 버는 경우)가 될 수 있음
즉 과대예측은 거의 공짜에 가깝게 봐주고, 과소예측만 DA-RT 스프레드만큼 벌점을 받는 구조입니다. 벌금비용률(penalty_rate)이 100%보다 작은 한 이런 비대칭이 항상 존재해서, 어지간한 예측오차는 gap에 크게 반영되지 않습니다.

원인 2: 우리 MISO 데이터의 DA-RT 스프레드가 생각보다 작음
블록9 테스트 기간(2013-09-24~2014-01-01) 실제 가격을 봤습니다:

원인 3: 오라클 정의가 gap 크기를 지배함 (이미 확인된 사실)
같은 데이터·비슷한 이익함수로도 operational_corrected는 오라클에 설비최대(1.0) 후보를 추가해서 gap이 51%까지 나왔습니다. 오라클을 얼마나 "낙관적"으로 잡느냐가 gap의 스케일 자체를 결정하는데, 논문 저자가 실제로 어떤 오라클/가격데이터로 12~15%를 얻었는지는 확인할 방법이 없습니다.

정리
**nRMSE 차이(우리 3239% vs 논문 2135%)**는 예측 정확도 자체의 차이지만
**gap 차이(우리 2.63.7% vs 논문 1215%)**는 예측 정확도보다는 ① 이익함수의 비대칭 구조, ② 우리가 쓴 MISO 가격 표본의 순 DA-RT 스프레드가 작다는 점, ③ 오라클 정의가 훨씬 크게 작용한 결과입니다.
논문이 어느 MISO 노드/기간을 썼는지 공개하지 않아서(§6 한계), 저자의 가격 데이터가 우리 것보다 DA-RT 스프레드가 훨씬 컸을 가능성이 gap 차이의 가장 그럴듯한 설명입니다 — 이건 코드로 검증 불가능한, 데이터 자체의 한계입니다.
